# WinTAK 5.7 — Parity Gap Report (C-17)

**Owner:** WP3. **Status:** gap analysis complete; **full re-fork deliberately NOT attempted** —
descoped by the owner as too large for the remaining budget. Two bounded, safety-relevant fixes
were applied (§5). Everything else below is **deferred**.

**Reference tree: `WinTAK5.6/`. 5.7 must never be backported into 5.6.**

---

## 1. What C-17 actually is

`git log` shows `94ef70b` ("WinTAK: display-config symbology, Mission Package send, send-item-to-PLI")
landed **before** `c1cce67` ("Add ATAK 5.7 and WinTAK 5.7 port scaffolds"). The 5.7 scaffold was
branched from an **older working tree** and never rebased. It is a *stale fork*, not a port.

The audit rated this the most serious defect the cross-cutting pass found, and the reason is not
the missing features on their own — it is that both trees shipped **the same identity**:

| | 5.6 (before) | 5.7 (before) |
|---|---|---|
| `MANIFEST.xml:4` `<id>` | `FeatureLink` | `FeatureLink` |
| `MANIFEST.xml:5` `<version>` | `2.6.9` | `2.6.9` |
| `AssemblyVersion` | `1.0.0.0` | `1.0.0.0` |
| `AssemblyName` / `PluginName` | `FeatureLink` | `FeatureLink` |

Two materially different binaries, one of them regressed, indistinguishable to the plugin manager,
to a crash dump, and to a support engineer reading a manifest. That is the shipping hazard, and it
is what §5 fixes.

## 3. Behavioural regressions in 5.7, verified at the cited lines

These are the ones that matter operationally. All verified against the working tree.

1. **`ViewModels/FeatureLinkDockPane.cs:878`** — `if (visible) _cotSender.Process(cotEvent);`
   5.6 always posts then sets `MapItem.Visible`. **Downloading a layer while hidden posts nothing**,
   so a later "show" toggle reveals nothing — the eye icon is permanently broken for that layer
   until a re-download. *(Confirmed: the surrounding comment still claims no per-item visibility
   API exists, which 5.6 has since disproved.)*
2. **`:744-749` `OnToggleLayerVisibility`** — sets `layer.Visible` and saves, but never calls
   `SetLayerMarkersVisible`; **that method does not exist in this tree at all** (grep count: 0).
   Hiding a layer leaves every marker on the map.
3. **`:784-820` `DownloadLayerAsync`** — no `previousUids` diff (grep count: 0). Features deleted
   server-side leave **orphan markers on the map forever**. Combined with the unstable-uid defect
   this grows without bound. In a SAR/PLI context that is a stale-track hazard, not cosmetic.
4. **Mission Package layer share is entirely absent** — no `OnShareLayer`, no
   `BuildShareConfigJson`, no `ShareLayerCommand`, no `IContactService` import, no
   `ContactPickerWindow`. The flagship interoperability feature does not exist here.
5. **"Send Item to PLI Layer" is entirely absent** — no `RecentCotItems`,
   `SendItemToLayerCommand`, `OnPreviewCotBroadcast`, or `Models/RecentCotItem.cs`.
6. **`:1013,:1028`** — PLI `how` hardcoded `"m-g"`, `group_name`/`group_role` sent empty. 5.6 pulls
   real values from `GetSelfCotEvent()`. Every PLI row from a 5.7 client is missing team/role
   attribution.
7. **`Models/ArcGisLayer.cs`** — `LblJson`/`PopupJson` deleted → silent persistence data loss
   across a 5.6 → 5.7 downgrade.
8. **`libs/` is empty on disk (0 files)** while `FeatureLink.csproj:68-105` references nine
   assemblies by `HintPath`. **5.7 cannot compile as delivered.** *(5.6 has a `VerifySdkLibs`
   target that fails with one clear message; 5.7 does not yet.)*

Plus every defect that was in the shared files before remediation — C-06, C-09, C-19, C-21, C-22,
C-26, C-27 — is still present in 5.7, because those files were byte-identical and only 5.6 was
fixed.

## 4. Recommended port order

The correct fix remains the prescribed one: **re-fork 5.7 from current 5.6** and keep only the
legitimate SDK differences. Doing it incrementally instead is more expensive and re-creates the
drift. But if it must be staged, this is the dependency order — each phase is independently
shippable-to-a-test-bench and each depends on the ones above it.

| Phase | Work | Est. |
|---|---|---|
| **0** | *(done, §5)* Identity split + `.wpk` packaging + build guard. | — |
| **1** | Copy `libs/` in, add a `VerifySdkLibs` target, get the **current** 5.7 tree to compile. Nothing else can be validated until this is true. | 0.5 d |
| **2** | Copy the five new leaf services verbatim (`Log.cs`, `SafeJson.cs`, `UrlGuard.cs`, `ArcGisHttp.cs`, `AutoSymbology.cs`) + `DisplayStyleResolver.cs`; **delete `IconResolver.cs`**; update the two call sites and the csproj `Compile` list. No SDK types involved, so this is a straight copy. | 0.5 d |
| **3** | Copy `Services/ArcGisFeatureService.cs`, `Services/ArcGisAuthService.cs`, `Services/SettingsStore.cs`, `Models/DownloadedFeature.cs` verbatim. Restore `LblJson`/`PopupJson` on `ArcGisLayer` and copy 5.6's version. Closes C-06/C-09/C-19/C-21/C-22 on 5.7. | 0.5 d |
| **4** | Copy `Models/RecentCotItem.cs`, `Views/ContactPickerWindow.xaml(.cs)`, `Services/DialogService.cs`, and the 7 missing PNGs; add the csproj `Compile`/`Page`/`Resource` entries. | 0.5 d |
| **5** | Replace `ViewModels/FeatureLinkDockPane.cs` wholesale with 5.6's. **This is the bulk of the work and the only phase with real risk** — it is where any genuine SDK 5.7 API difference will surface. Expect to reconcile `MapItem.Visible`, `MapItem.Dispose()`, `MapMarker.Color` and `ICommunicationService.SendMissionPackage` against the 5.7 assemblies. | 1.5–2 d |
| **6** | Replace `Views/FeatureLinkView.xaml` with 5.6's, re-enable the share and upload buttons, restore `EyeIconSource`. | 0.5 d |
| **7** | Point `Tests/FeatureLink.Tests` at both trees (add a second `TargetFramework`-agnostic link set, or parameterise `RepoLocator`), so the binding smoke test guards 5.7's XAML too. | 0.5 d |
| **8** | Add the drift guard the audit asked for: either collapse to one shared source project (`FeatureLink.Shared.projitems` / linked `<Compile Include="..\Shared\**">`) with only `AssemblyInfo`/csproj differing per SDK — **the only defensible answer at this scale** — or CI that runs `git diff --no-index` across the shared file list and fails on unexpected divergence. | 1 d |

**Total: ~6–7 engineer-days**, of which phase 5 is the only one that can overrun.

**Phases 1–4 are low-risk verbatim copies.** If budget is tight, doing 1–4 alone closes every
*security* finding on 5.7 (C-09, C-19, C-21, C-22, C-02 partially) while leaving the *feature*
regressions — which is a defensible interim position, and much better than the current one.

## 5. What was actually fixed in this pass (bounded)

### 5.1 Identity collision — `MANIFEST.xml`, `AssemblyInfo.cs`, `FeatureLink.csproj`

| Field | Was | Now |
|---|---|---|
| `<id>` | `FeatureLink` (same as 5.6) | `FeatureLink.WinTAK57` |
| `<version>` | `2.6.9` (same as 5.6) | `0.9.0-pre` |
| `AssemblyVersion` | `1.0.0.0` (same as 5.6) | `0.9.0.7` (4th field = SDK minor) |
| `PluginName` | `FeatureLink` (same as 5.6) | `FeatureLink (5.7 pre-release)` |
| `WpkVersion` | `2.6.9` | `0.9.0-pre` |

The version is deliberately **not** 2.7.0. This tree is not at parity with 5.6 and must not claim
to be; `0.9.0-pre` states what it is. The manifest description and the assembly description both
now say **"INCOMPLETE PORT — not for release"** and enumerate what is missing, and the `PackageWpk`
target emits an MSBuild **warning** on every Release build.

Licence metadata (C-36) was added at the same time since it was the same edit.

### 5.2 C-18 — `.wpk` omitted `Newtonsoft.Json.dll`

`WinTAK5.7/build-wpk.py` was byte-identical to 5.6's and had the identical defect: the package
contained only `FeatureLink.dll`, the icon and an inline manifest, while `packages.config` pins
`Newtonsoft.Json 13.0.3`. 5.6's fixed script was copied across and the csproj now passes
`--manifest`.

**Verified by execution** under Python 3.13:

```
WPK written: w57/out.wpk
  plugin:       FeatureLink.dll
  dependencies: Newtonsoft.Json.dll
  manifest.xml
  icon.png
  plugin/x64/FeatureLink/FeatureLink.dll
  plugin/x64/FeatureLink/Newtonsoft.Json.dll
5.7 id      : FeatureLink.WinTAK57
5.7 version : 0.9.0-pre
```

### 5.3 A bug this exposed in `build-wpk.py` (both trees)

The 5.7 manifest documents the C-17 collision by quoting the old `<id>` and `<version>` elements
verbatim inside an XML comment. `replace_element` used a naive `str.find`, so it rewrote the text
**inside the comment** instead of the live element — the first generated 5.7 package declared
`<id>FeatureLink</id>`, i.e. exactly the identity the comment was warning about.

Caught by running the script against the real manifest rather than a fixture. `replace_element`
now computes comment spans and substitutes only outside them; fixed in **both** trees, and both
were re-verified afterwards (5.6 → `id: FeatureLink`, `version: 2.7.0`, `license: Apache-2.0`).

### 5.4 Build robustness

`DeployPlugin` made conditional and overridable via `FEATURELINK57_PLUGIN_DIR`, matching 5.6 — the
hardcoded `D:\Apps57\Plugins\` failed every Debug build on any other machine. Dependencies are now
copied alongside the DLL for live deployment.
